## What we are checking for

The claim under test is narrow and specific:

> No one has published a **controlled ablation of guardrail strictness** for agentic delivery, reporting both throughput cost and gate yield.

Four facts determine whether that holds. Each needs a yes/no answer.

| # | Fact to establish | If yes, what changes |
| --- | --- | --- |
| F1 | A controlled guardrail ablation already exists | Pivot to replication + extension, or differentiate hard on gate yield and intervention-cost accounting |
| F2 | A reusable guardrail-adoption dataset over agent-PR repositories exists | Drop the scrape, cite and reuse it. Saves a week, costs a contribution |
| F3 | Vendor evaluations of AI code review report precision/false-positive rates | We lose the "nobody measures this" framing for G3; keep it for the *cost* side |
| F4 | Pre-AI empirical work already quantifies required-review overhead | We inherit a baseline instead of inventing one, which strengthens the paper |

F2 is the most valuable single answer and the cheapest to get. Start there.

## Search protocol

Run each of these and record the top hits. Breadth matters more than exhaustiveness.

**Queries**

1. `guardrail` / `guardrails` + `agentic` + `pull request` + `empirical`
2. `code review bot` + `precision` + `false positive` + `empirical study`
3. `branch protection` OR `rulesets` OR `required checks` + `adoption` + `empirical`
4. `AI code review` + `controlled experiment` + `developer productivity`
5. `agentic pull request` + `ablation` / `counterfactual` / `causal`
6. `human-in-the-loop` + `agent` + `latency` + `throughput`
7. `CI cost` + `developer productivity` + `measurement`
8. `code review` + `turnaround time` + `defect escape`

**Venues and indexes**

- arXiv `cs.SE`, last 18 months, sorted by date
- ACM DL and IEEE Xplore for MSR / ICSE / FSE / ASE proceedings
- The MSR mining challenge list for the current and next cycle — confirm the theme, because if it is agentic PRs, that is the venue and its deadline drives the milestone plan
- Google Scholar forward-citations of the four leads above
- GitHub search for `agent evaluation harness`, `guardrail benchmark` — the long tail is where duplicates hide

**Read in full, not skimmed**

- The two MSR 2026 intervention and rejection papers: read for methodology, so the design differs where it must and reuses where it can
- The AI-review-recall paper: read its limitations section, which is where our differentiation lives

## Novelty decision

| Finding | Action |
| --- | --- |
| F1 no, F2 no, F3 no | Proceed as scoped. Lead with the gap; the adoption dataset becomes a second contribution |
| F1 no, F2 yes | Proceed. Drop the scrape, reuse the dataset, focus effort on the controlled layer |
| F1 no, F3 yes | Proceed, but reframe: not "nobody measures review gates" but "nobody measures what they *cost* in throughput and review latency". Still defensible |
| F1 yes, but observational only | Proceed. The contribution is the counterfactual, not the correlation |
| F1 yes, controlled and equivalent | **Stop and rethink.** Either scope to a differentiated replication (gate yield, intervention-cost accounting, GitHub-native rungs) or choose a different project. Do not build the same study |

Record which row applies, in one paragraph, at the top of `lit-review.md`. That paragraph is the project's novelty claim and it will be the first thing any reviewer reads.
